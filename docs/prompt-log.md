# Журнал запросов и решений

## Архитектура Delul

### Запрос

«Предложи архитектуру веб-приложения Delul на основе Must-историй US-1–US-4: какие части нужны, как они связаны. Дай Mermaid flowchart. Проверь предложения по пяти признакам и найди минимум два избыточных решения».

Проект: преподаватели университета создают тесты и просматривают результаты, студенты проходят тесты и разбирают ошибки.

### Что предложил агент

Основной вариант: один веб-интерфейс, единый сервер приложения с маршрутизаторами, сервисами и репозиториями, PostgreSQL и вход через Keycloak. Отдельная база Keycloak хранит данные аутентификации. Диаграмма и подробности находятся в [architecture.md](architecture.md).

Для критического сравнения также предложены два дополнительных варианта: распределение приложения на микросервисы с API Gateway и очередью, а также Redis для кэширования. Они не включены в итоговую схему MVP.

### Оценка предложений

Пять признаков выбраны для этой проверки, поскольку в задании их список не приведён: связь с Must-историями; соответствие масштабу; сложность разработки и сопровождения; необходимость в данных и безопасности; наличие более простой альтернативы.

| Что предложено | Почему отклонено для MVP | Решение вместо |
|---------------|--------------------------|----------------|
| Микросервисы тестов, попыток и проверки, API Gateway и очередь | Must-истории не требуют распределённой обработки. Нет данных о нагрузке. Несколько сервисов усложняют запуск и единое сохранение ответов, статуса и результата. | Один сервер приложения с внутренними модулями и общей транзакцией PostgreSQL. |
| Redis для кэширования тестов и результатов | Нет измеренной проблемы скорости. Нужно дополнительно обеспечивать актуальность кэша и не раскрывать результаты до разрешения преподавателя. | PostgreSQL, индексы и ограничение размера списков. Вернуться к кэшу после измерений. |

### Что сохранено в предложенной архитектуре

- Веб-интерфейс для двух ролей.
- Единый сервер: проверка доступа, создание и публикация тестов, отправка ответов, расчёт и выдача результатов.
- PostgreSQL с таблицами существующей ER-модели.
- Keycloak для входа; пароли не хранятся в таблицах приложения.

Это оценка и предложенные решения агента. Личное подтверждение автором проекта не зафиксировано; журнал не приписывает пользователю решения, которых он ещё не сообщал.


## Приведение архитектуры к шаблону урока 6

Запрос: оформить собственную архитектуру по образцу, изменить первую строку и стрелку AI, заполнить таблицу компонентов; сохранить минимум два отклонённых предложения.

Результат: в `architecture.md` добавлена схема `flowchart LR` с Next.js, FastAPI, PostgreSQL и Keycloak, а также таблица всех компонентов схемы. Номера уроков, кроме указанного в образце диапазона 7–9 для backend, не придуманы.

Дополнительно исключены Ollama и стрелка AI: обязательные истории не требуют AI-функций, а ответы проверяются сравнением с заданными вариантами. Два ранее отклонённых предложения — микросервисы с очередью и Redis — сохранены выше вместе с причинами отказа.
