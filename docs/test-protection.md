# Защита прохождения тестов

Страница студента: `/test`. Swagger: `/api/docs`. Контроль сочетает ограничения сервера и браузера; это не специализированный экзаменационный браузер.

## Правила

| Правило | Как работает |
|---------|--------------|
| Одна попытка | UNIQUE(user_id, quiz_id) в attempts и проверка в транзакции. Начало сразу расходует попытку, включая закрытую, заблокированную и просроченную |
| Вход | HttpOnly cookie-сессия: случайный токен, в БД только SHA256 токена, срок 8 часов, SameSite=Strict; Secure включён вне local |
| Роли | Публичная регистрация создаёт только student. Преподавателей назначает admin. Учебная демоличность по умолчанию отключена |
| Исходная вкладка | При начале выдаётся отдельный ключ попытки. В БД только его хеш; в интерфейсе ключ хранится в sessionStorage исходной вкладки. Он нужен для получения вопросов, сохранения, heartbeat, событий и завершения |
| Уход со страницы | Первый эпизод visibilitychange/blur/выхода из fullscreen/pagehide — предупреждение; второй — blocked. Один event_id учитывается один раз |
| Пропажа связи | Heartbeat каждые 5 секунд в активной вкладке. Если его нет более 45 секунд, сервер закрывает попытку при следующем обращении |
| Время | time_limit_minutes от 1 до 180, по умолчанию 30. Deadline хранится на сервере и не сбрасывается перезагрузкой. По истечении — expired с результатом сохранённых ответов |
| Порядок | Вопросы и варианты перемешиваются один раз и сохраняются в попытке; перезагрузка не меняет порядок |
| Сохранение | Ответы сохраняются по ID вопросов/вариантов. Чужие и повторяющиеся вопросы, чужие варианты не принимаются |
| Копирование | CSS user-select, запрет copy/cut/contextmenu/drag, распространённых комбинаций копирования/печати/сохранения и печатная CSS-версия без вопросов |
| Наблюдение преподавателя | Автор и admin видят имя, группу, статус, deadline, число уходов и причину блокировки; другие преподаватели и студенты не имеют доступа |

Перед стартом студент видит правила и подтверждает согласие. Страница запрашивает полный экран; если браузер его не предоставляет, остаётся контроль видимости и фокуса. Ограничения копирования действуют только во время попытки. Выход из вкладки не предотвращается средствами сайта — регистрируется событие и меняется доступ.

## Что не гарантируется

Нельзя надёжно запретить Google Объектив, фотографирование другим устройством, системный снимок экрана или извлечение уже полученных данных из браузера. События фокуса сообщаются клиентом и могут быть обойдены технически подготовленным пользователем. Ключ вкладки также можно скопировать через инструменты разработчика: это защита от обычного повторного открытия, а не криптографическая привязка к устройству.

Одна попытка — **на аккаунт**, а не доказанно на физического человека. Без университетского SSO, проверки личности или списка допущенных студентов нельзя исключить регистрацию второго аккаунта. Приложение не собирает камеру, микрофон, снимки экрана или историю посещений. Уход из вкладки сам по себе не доказывает списывание: системные окна, вспомогательные технологии и перебои сети тоже могут вызвать событие. Спорную блокировку должен разбирать преподаватель; автоматического обвинения или сброса попыток нет.

## Состояния

- in_progress: можно читать вопросы и сохранять ответы при наличии сессии и ключа вкладки.
- submitted: завершено студентом, выдаются баллы, новые ответы и повторное начало недоступны.
- expired: время истекло, учитываются сохранённые ответы, повторное начало недоступно.
- blocked: повторный уход или потеря связи; вопросов и баллов студенту больше не выдаёт.

Проверка deadline и heartbeat выполняется на сервере при обращении. Отдельного фонового планировщика нет, поэтому в БД статус может обновиться при следующем запросе студента или преподавателя; доступ после истечения всё равно не возобновляется.

## Подготовка

1. Применить миграции из backend: `alembic upgrade head`.
2. Выполнить `python seed.py`.
3. Задать пароль существующему преподавателю или admin локально: `python manage.py set-password teacher@demo.kz`. Пароль вводится скрыто, не задаётся аргументом и не печатается. Команда отзывает старые сессии.
4. Войти через `/api/auth/session` или страницу `/test`. Для проверки управления тестами используйте Swagger от роли teacher/admin; преподаватель может задать время через POST/PATCH теста.
5. Не включать ALLOW_DEMO_AUTH для настоящего прохождения. По умолчанию false. Для учебной проверки прежней демоличности можно явно включить true только в local; защищённые попытки всё равно требуют настоящую cookie-сессию.

0003_protected_attempts не удаляет историю. Если в старой БД уже есть несколько попыток одного аккаунта на один тест, миграция останавливается до изменения таблиц и требует ручного разбора дубликатов. Старые незавершённые попытки без deadline при обращении становятся expired; новая попытка не выдаётся.

## Проверка

Проверяются сессии и выход, запрет публичного teacher/admin, уникальность попытки на уровне БД, исходная вкладка, сохранность случайного порядка после перезагрузки, отсутствие правильных ответов, частичное сохранение, завершение, дедупликация событий, блокировка, серверный deadline, потеря heartbeat, чужой аккаунт, откат транзакции и просмотр преподавателем. Миграции проверены на временной SQLite и компиляцией SQL для PostgreSQL.

В браузере на отдельной тестовой БД проверены вход, правила с обязательным согласием, начало с таймером, выбор и сохранение ответа, завершение с результатом и отсутствие кнопки повторного старта. Рабочая БД для этой проверки не использовалась.
